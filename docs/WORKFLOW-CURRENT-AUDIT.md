# ผลตรวจสอบ Flow การทำงานจริงของระบบ

ตรวจสอบเมื่อวันที่ 3 กันยายน 2569 จากโค้ดที่ระบบเรียกใช้และตาราง `WorkflowTransition` ในฐานข้อมูลปัจจุบัน

## แหล่งที่ตรวจสอบ

- การสร้างคำร้อง: `app/actions/f07-action.ts`
- การหาขั้นตอนที่ใช้ได้: `lib/workflow.ts`
- การอนุมัติ ส่งกลับ ดำเนินการ IT และปิดงาน: `lib/services/approvalService.ts`
- API ปุ่มดำเนินการ: `app/api/requests/[id]/action/route.ts`
- การแก้ไขและส่งคำร้องที่ถูกส่งกลับ: `app/api/requests/[id]/route.ts`
- รายการงานรอดำเนินการ: `lib/pending-tasks-shared.ts`
- ข้อมูลจริงในฐานข้อมูล: `Category`, `Status`, `Action`, `WorkflowTransition`, `WorkflowStep` และ `SpecialApproverMapping`

## Flow หลักที่ตั้งอยู่ในฐานข้อมูลปัจจุบัน

ทุกหมวดเริ่มด้วยเส้นทางเดียวกันดังนี้

1. ผู้ขอสร้างคำร้อง → `PENDING`
2. หัวหน้าแผนกอนุมัติ → `WAITING_ACCOUNT_1`
3. บัญชีตรวจรอบที่ 1 → `WAITING_FINAL_APP`
4. ผู้อนุมัติสูงสุดอนุมัติ → `IT_WORKING`
5. IT Operator ดำเนินการเสร็จ → `WAITING_ACCOUNT_2`
6. บัญชีตรวจรอบที่ 2 → `WAITING_IT_CLOSE` → IT Reviewer ยืนยัน → `CLOSED`
   - ทุกหมวดใช้เส้นทางเดียวกัน รวมถึง `คลังสินค้า`

## การส่งกลับแก้ไข

- ทุกสถานะที่มีผู้รับผิดชอบใน Flow ปัจจุบันมี Action `REJECT`
- เมื่อกดส่งกลับ สถานะเปลี่ยนเป็น `REVISION`
- ผู้ขอแก้รายละเอียดหรือไฟล์แนบ แล้วกดส่งคำร้องใหม่
- API เปลี่ยนสถานะจาก `REVISION` กลับเป็น `PENDING`
- ระบบลบ `ApprovalHistory` เดิมของคำร้อง แล้วเริ่มพิจารณาใหม่จากหัวหน้าแผนก

## ข้อค้นพบสำคัญ

1. **ฐานข้อมูลปัจจุบันกำหนดให้บัญชีตรวจ 2 รอบทุกหมวด** ไม่ได้มีบางประเภทที่ตรวจเพียงรอบเดียว
2. ทุกหมวด รวมถึง `คลังสินค้า` ใช้เส้นทางเดียวกัน เพื่อให้ผู้ใช้ไม่ต้องจำข้อยกเว้น
3. โค้ดรองรับ `WorkflowTransition` เฉพาะ `CorrectionType` แต่ฐานข้อมูลปัจจุบันมี Transition เฉพาะประเภทจำนวน **0 รายการ**
4. ตาราง `WorkflowStep` และ `SpecialApproverMapping` ปัจจุบันไม่มีข้อมูล เส้นทางที่ทำงานจริงจึงยึด `WorkflowTransition`
5. ค่า `requiresCCSClosing` ถูกทำให้เป็น `true` ทุกหมวดเพื่อให้สอดคล้องกับ Flow กลาง ขณะระบบทำงานสถานะถัดไปอ่านจาก `WorkflowTransition` โดยตรง

## ผลต่อกฎ “ไม่ใช่ทุกการแก้ไขต้องให้บัญชีตรวจ 2 ครั้ง”

กฎนี้ยังไม่ตรงกับค่าที่ตั้งอยู่ในฐานข้อมูล ณ วันที่ตรวจสอบ หากต้องการให้บางประเภทการแก้ไขผ่านบัญชีเพียง 1 รอบ ต้องสร้างหรือแก้ `WorkflowTransition` ของหมวด/ประเภทการแก้ไขนั้นก่อน จากนั้นระบบและแผนภาพจึงจะแสดงเส้นทางดังกล่าวได้อย่างถูกต้อง
